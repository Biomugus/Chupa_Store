# 0003 Хранение заказов и обращений в Supabase, уведомления по нескольким каналам

## Статус

Принято.

## Контекст

Заказы (`POST /api/orders`) и обращения (`POST /api/feedback`) только пересылались сообщением в Telegram и нигде не сохранялись. Если Telegram не принимал сообщение, заявка оставалась лишь в `console.error`.

С 2026 года Telegram в РФ замедлен и блокируется. В проде запрос к Telegram делает функция Vercel за рубежом, так что VPN покупателя роли не играет. Но зависеть от одного внешнего канала как от единственного места хранения заказов рискованно.

## Решение

1. Заказ и обращение **сначала сохраняются** в Supabase — таблицы `orders` и `feedback_requests` (миграция `008`). Запись делает сервер через admin-клиент с `service_role`, таблицы закрыты RLS без политик.
2. После ответа покупателю (`after()` из `next/server`) уведомление уходит во все настроенные каналы параллельно: Telegram-бот, VK (ЛС основателям или беседа сообщества), рабочая почта по SMTP. Каналы работают по принципу best-effort, итог пишется в колонку `notifications`.
3. Ошибкой для покупателя считается только сбой записи в БД (500). Сбой уведомлений на ответ не влияет.
4. Идемпотентность по `clientRequestId` — уникальный `orders.client_request_id`. Повтор возвращает тот же заказ без повторных уведомлений.

## Последствия

- Заявка не теряется при недоступности любого канала. Пропущенные уведомления видны в `notifications` и в логах.
- Новые env: `SUPABASE_SERVICE_ROLE_KEY`, `VK_*`, `SMTP_*`, `NOTIFY_EMAIL_TO`. Telegram (`TG_*`) стал необязательным.
- Появился третий клиент Supabase — admin (`shared/api/supabase/admin.ts`), только для серверного кода.
- Заявки просматриваются и меняют статус в Supabase Dashboard. Отдельной админ-страницы пока нет.
- **Риск 152-ФЗ:** персональные данные покупателей (ФИО, телефон, контакт) хранятся в Supabase за пределами РФ, а закон требует изначальной записи в БД на территории РФ. Для MVP риск принят. Перед масштабированием нужно оценить переезд хранения на российскую инфраструктуру.

## Альтернативы

- **Оставить только Telegram** — заявки теряются при любом сбое Telegram API.
- **MAX-бот** — с осени 2025 боты доступны только верифицированным юрлицам РФ. Можно добавить отдельным каналом в `notifications/`, если появится ИП или ООО.
- **Только БД + админ-страница без push** — заявки легко пропустить. Остаётся возможным следующим шагом поверх текущего решения.
